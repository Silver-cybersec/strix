## 2. 架构

结论：宿主进程驱动模型和工具；shell 在容器里跑；stdio MCP 在宿主跑。README 里的自动渗透和自动修复，靠的是容器内任意命令加上默认可写的源码挂载。

- 宿主：CLI/TUI（`strix/interface`）、编排（`strix/core`、`strix/agents`）、报告（`strix/report`）、云 CLI（`strix/interface/cloud`，默认 `https://app.strix.ai`）。云令牌经 `write_secret_text` 写成 `~/.strix/platform-auth.json`，模式 `0o600`（`strix/utils/secret_files.py` 12–22 行，`strix/interface/platform_cli.py` 34、79 行）。
- 沙箱：唯一内置后端是 Docker（`strix/runtime/backends.py` 54–58 行）。`session.exec` 在容器内执行，对应 SDK 的 `exec_command`。`strix/agents/factory.py` 505–521 行在执行前可选地走审批，workdir 超出 `/workspace` 时由 SDK 拒绝。
- 白盒：本地目录 bind 到 `/workspace/<子目录>`（`strix/runtime/session_manager.py` 69–81、282–284 行）。克隆仓库落在临时目录 `strix_repos/<run>`（`strix/interface/utils.py` 1562 行），再挂进去。
- MCP：`stdio` 由宿主 Python 进程拉起子进程（`strix/tools/mcp/client.py` 144–152 行）。用户配置的 command 不在沙箱里。HTTP MCP 出网，401 时在内存里刷新 bearer（`strix/tools/mcp/auth.py`）。
- 代理：容器入口启动 Caido；宿主用游客令牌连发布端口（`strix/runtime/caido_bootstrap.py`）。
- Viewer 默认绑 `127.0.0.1`（`strix/interface/viewer/cli.py` 48–51 行）。审批与转向要求会话 cookie（`strix/interface/viewer/server.py` 455–458、533–541 行）。`--host 0.0.0.0` 是操作者显式选项，链接本身就是能力。
- 系统提示把扫描写成已获授权、不要等待批准（`strix/agents/prompts/system_prompt.jinja` 69–86 行）。这与「只测用户指定目标」的约束主要在提示词里，不在默认的网络策略里。
- 未读 app.strix.ai 服务端。自注册的非 Docker 后端只看到注册函数，没有随仓库提供的第二种运行时。

### 3.2 对部署者／宿主机的真实风险

结论：高风险来自默认沙箱能改宿主项目并以 root 身份写挂载、还能碰到宿主网络；审批默认不挡。另有 Caido 游客面和默认遥测。未把产品自带的攻击说明算成后门。

- **高 · STRIX-20261126-001** 默认隔离不够。容器总是加上 `NET_ADMIN`、`NET_RAW`，并设置 `host.docker.internal=host-gateway`（`strix/runtime/docker_client.py` 244–267 行，[链接](https://github.com/usestrix/strix/blob/9ed84f99c8f13fc921baebc59e0c696108cfab3e/strix/runtime/docker_client.py#L244-L267)）。本地目标默认 `read_only` 为假（`strix/interface/utils.py` 1320–1327 行）。`.git`、`.agents`、`.codex` 在可写树上会再盖一层只读（`strix/runtime/session_manager.py` 80、230–244 行），其余文件可写。镜像给 pentester `NOPASSWD:ALL`（`containers/Dockerfile` 42–45 行）。Linux 上入口用 sudo 把 uid 改成宿主 uid（`containers/docker-entrypoint.sh` 3–17 行），代理仍可再 sudo 回 root。没有 user namespace、只读根文件系统或默认 cgroup 上限（上限在 96–117 行，不设置环境变量就不开）。`SYS_ADMIN` + `apparmor:unconfined` 仅当 manifest 需要 FUSE/NFS/S3（233–243 行）；默认 Manifest 只有环境变量，docker 后端的 entries 为空（`session_manager.py` 305–331 行）。对照锁定的 openai-agents 0.19.0 上游源码，这两项由 Mount 模式触发。未在本机导入该 wheel 复核。动作审批默认 `enabled=False`（`strix/config/settings.py` 146 行）。模块写明检查挡的是粗心，命令文本来自代理自己（`strix/core/action_approvals.py` 3–6、41–43、335–338 行）。未挂载 `docker.sock`，也未设置 `privileged`。挂载前会拒绝家目录、一批系统目录和 `.ssh` 等名字（`utils.py` 1406–1439 行），挡不住项目树内部的文件。
- **中 · STRIX-20261126-002** Caido 听 `0.0.0.0:48080`，`--allow-guests`，PKCS#12 导出口令为空（只记 `containers/docker-entrypoint.sh` 41–47 行与 `containers/Dockerfile` 75–90 行）。宿主发布到 `127.0.0.1`（`docker_client.py` 244–247 行）。`loginAsGuest` 无认证（`caido_bootstrap.py` 26–28、46–55 行）。注释写的是容器内 127.0.0.1，入口实际是 0.0.0.0。本机进程或同桥其他容器可以游客登录并读取代理流量。
- **低 · STRIX-20261126-006** 遥测默认开，发 PostHog 与 Scarf。已读载荷不含目标 URL、发现正文或异常消息（`strix/telemetry/posthog.py` 25–26、59–91 行；`_common.py` 50–56、87–96 行）。项目写入键在该常量，正文不抄录。`STRIX_TELEMETRY` 可关。
